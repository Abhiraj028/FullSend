## signaling server rendezevous protocol

Host creates room
→ server generates UUID
→ host shares URL with room UUID
→ guest requests entry
→ host approves/rejects
→ server marks room as paired
→ server relays WebRTC setup messages only between those two sockets

## frontend room flow

connect to the signaling server
→ create room
→ place room ID in URL
→ open URL elsewhere
→ request entry
→ approve/reject request


## webrtc setup flow

Host browser                         Signaling server                    Guest browser
─────────────                        ────────────────                    ─────────────
create RTCPeerConnection
create two DataChannels
create offer
set local description
      offer ───────────────────────→ forwards offer ───────────────────→ set remote description
                                                                        create answer
                                                                        set local description
      ←────────────────────── answer forwarded ←─────────────────────── answer

ICE candidates flow both directions until a usable direct route exists.

--

An SDP offer is text metadata generated by WebRTC. It says roughly:
I support a data channel.
Here are the connection parameters I can use.
Here is my DTLS identity/fingerprint.
Here are the media/data transport details I propose.
The guest applies that offer, creates a compatible answer, and sends it back.
Neither is file data. They are setup documents.

## flow

server sends: room-paired
          ↓
host calls startHostConnection()
          ↓
host creates RTCPeerConnection
          ↓
host creates control + file data channels
          ↓
host creates offer
          ↓
offer goes through WebSocket → server → guest
          ↓
guest handleSignal() receives offer
          ↓
guest creates RTCPeerConnection
          ↓
guest applies host offer, creates answer
          ↓
answer goes through WebSocket → server → host
          ↓
host handleSignal() applies answer
          ↓
both sides exchange ICE candidates as they discover routes
          ↓
WebRTC becomes connected
